## 迁移步骤

1. clone本仓库，按README安装独立Python运行环境并运行离线测试。
2. 安装模拟器/游戏/ALAS，人工登录；只运行一个账号控制器。
3. 复制settings.example.json至settings.json，填写服务器实际ADB路径、serial、ALAS目录、ALAS自带Python和profile。serial从adb devices读取，不写死5555或emulator-5554。
4. 依daily-growth-policy.md建立新profile，先关闭Main/Event和其它未经现场验证任务。识别游戏主页、更新当天舰队/等级/心情/资源，再选有限练级批次。旧活动和旧日期脚本禁止恢复。
5. 如需DeepSeek，将密钥存服务器用户环境，先用免费离线验证，模型调用单独小样本验收；不把秘钥写Git或命令历史。
6. 邮件继续每两小时主管事实报告；迁移后必须重新接入发送渠道。src.workers只生成草稿，不能因为模型返回成功就记邮件已发；记录发送系统返回的成功ID，失败/未知先查重。
7. 本机Codex心跳并非仓库内服务，clone不会自动迁移任务；在服务器所属主管环境按下面模板重建。不要把本机配置目录、Gmail令牌或凭据打包。
8. 关闭本机控制器、暂停本机自动化、确认无人同时登录/操作后，才启动服务器端。服务器实测连接、单任务、暂停/恢复、掉线与远程断开，再进行24小时试运行。

## 主管心跳模板（不含账号数据）

- 默认每30分钟检查，后台不抢前台、离线不启动模拟器、异地登录立即停并通知。
- 按daily-growth-policy.md先固定收益再稳定主线；彩船金船先主力后带练；每批1-3关，验收真实END、资源和逐舰心情后才继续。
- 不恢复历史活动/日期脚本，不买油钻、不自动建造兑换；低油/心情/满坞遵守保护与原图恢复。
- 每两小时把当天实际进度、资源净变化、培养舰进度和异常发送到操作者配置的邮箱；未知数注明最后实测时刻。已发ID去重；模型观察要人工/独立原图核验。
- 停止指令立即安全停本任务父子进程与定时器、写暂停标记并暂停主管心跳。

## 当前平台边界

本项目supervisor明确仅支持Windows。Linux服务器可以保存仓库和运行部分离线模块，但不能直接宣称雷电/Windows主管可用；必须另设计安卓实例、ADB连接、进程管理及图形会话并验收。
